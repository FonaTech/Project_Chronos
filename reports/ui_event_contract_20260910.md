# Gradio 空输入事件修复（2026-09-10）

新页面的 `apply_best` 按钮在真实 Chromium 中发送两个输入；自动调参轮询发送零个输入。当前事件表中两者的编号相邻，分别为 95、96。旧页面保留旧事件表后，把零输入轮询发到 `apply_best`，可以复现用户报告的错误。此前仅通过 Python `process_api` 测试，未覆盖浏览器与服务事件版本不同的场景。

本次增加了浏览器与服务实例的事件契约：页面为事件请求附带版本标识，服务在 Gradio 入队前校验版本和输入数量。旧页面的错位请求返回明确的刷新提示，不执行回调；合法的空输入轮询继续正常运行。未携带浏览器标识的合法 API 调用仍受支持。

浏览器会定期检查服务版本，并在服务更新或收到版本不匹配响应后重新加载页面。HTML 和 `/config` 禁用缓存，确保刷新取得同一版本的事件表。浏览器同步脚本已加入 wheel 的包数据。

验证：

- 完整测试：`python -m pytest -q tests`，**129 passed**。
- 8 项 HTTP 契约测试覆盖旧版本请求、零输入错调、正常按钮调用、合法轮询和缓存头。
- 3 项真实浏览器测试覆盖按钮与轮询的实际输入、错位请求被拒绝后仅刷新一次，以及旧服务页面自动刷新。
- 在隔离目录构建 wheel，确认包含 `ui/event_contract.py`、`ui/event_contract.js` 和启动器。
- 已确认当前 `127.0.0.1:7880` 服务启用了校验，`/config` 返回 `Cache-Control: no-store`。

首次应用时，仍在旧版本上打开的页面需要手动刷新一次，以加载浏览器同步脚本。后续服务更新会自动刷新同步。无效请求不会被填入默认配置后继续执行。
